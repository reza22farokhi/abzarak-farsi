راهنمای کامل فرمت JSON و رفع خطاهای رایج

دسته: برنامه‌نویسی و وب | زمان مطالعه: ۵ دقیقه

اگر شما یک برنامه‌نویس وب، موبایل یا حتی یک تستر API باشید، حتماً با فرمت JSON (مخفف JavaScript Object Notation) سروکار داشته‌اید. JSON یک استاندارد سبک برای تبادل داده بین سرور و کلاینت است که خوانایی بالایی برای انسان و ماشین دارد.

کد JSON شما خطا دارد؟

کد خود را در ابزار ما قرار دهید تا در کسری از ثانیه فرمت شده و خطاهای آن مشخص شود.

ابزار فرمت‌کننده JSON

JSON چه ساختاری دارد؟

ساختار JSON بر پایه دو عنصر اصلی بنا شده است:

  • Object (شیء): مجموعه‌ای از جفت‌های «کلید: مقدار» که در آکولاد { } قرار می‌گیرند.
  • Array (آرایه): لیستی از مقادیر که در کروشه [ ] قرار می‌گیرند.

۵ خطای بسیار رایج در JSON (و نحوه رفع آن‌ها)

برخلاف جاوااسکریپت، JSON قوانین بسیار سخت‌گیرانه‌ای دارد. اگر حتی یک کاراکتر اشتباه باشد، کل فایل نامعتبر می‌شود. این‌ها رایج‌ترین خطاها هستند:

۱. استفاده از کاما (,) در انتهای آخرین آیتم

در JSON، آیتم آخر نباید کاما داشته باشد. اگر بنویسید {"name": "Ali", "age": 30,} خطا می‌گیرید.

۲. استفاده از کوتیشن تک (') به جای کوتیشن دوتایی (")

در جاوااسکریپت می‌توانید از ' استفاده کنید، اما در JSON فقط استفاده از " مجاز است. {'name': 'Ali'} نامعتبر است.

۳. نظرها (Comments) در JSON

برخلاف زبان‌های برنامه‌نویسی، شما نمی‌توانید در JSON از // یا /* */ برای نوشتن توضیحات استفاده کنید.

۴. فراموش کردن آکولاد یا کروشه

این خطا در فایل‌های طولانی بسیار رایج است. هر { باید یک } و هر [ باید یک ] داشته باشد.

۵. کلیدهای بدون کوتیشن

در JSON، حتی کلیدها (Keys) هم باید داخل کوتیشن دوتایی باشند: {"name": "Ali"} درست است، اما {name: "Ali"} غلط است.

چرا فرمت‌دهی (Pretty Print) مهم است؟

وقتی داده‌ها را از یک API دریافت می‌کنید، معمولاً به صورت یک خط طولانی و فشرده (Minified) هستند. فرمت‌دهی یا Pretty Print کردن، این داده‌ها را با تودرتویی (Indentation) و فاصله‌گذاری مناسب مرتب می‌کند تا شما به راحتی بتوانید ساختار آن‌ها را بخوانید و اگر خطایی وجود دارد، پیدا کنید.

کد خود را همین الان تست کنید

ابزار ما علاوه بر فرمت‌دهی، صحت کدهای JSON شما را اعتبارسنجی می‌کند و اگر خطایی باشد، دقیقاً به شما می‌گوید در کدام خط است.
